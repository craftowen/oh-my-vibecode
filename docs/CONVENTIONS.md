# Code conventions — oh-my-vibecode

How code in this repo is written. [AGENTS.md](../AGENTS.md) owns *what* to build
and which patterns to use (auth, bindings, streaming, UI primitives); this file
owns *how it reads*: formatting, naming, module layout, comments, tests, git.

There is no linter or formatter configured on purpose (zero extra dev tooling).
The rules below are therefore the only enforcement — match the neighbouring
code, and when two files disagree, follow this document.

## 1. Formatting

Derived from the existing source (4k lines, 0 tabs, 0 single-quoted imports):

| Rule | Value |
|---|---|
| Indent | 2 spaces, never tabs |
| Quotes | double quotes in TS/TSX and JSX attributes; template literals only when interpolating |
| Semicolons | always |
| Trailing commas | on every multi-line list, object, parameter list and import |
| Line width | wrap around 80; 100 is the practical ceiling. Long Tailwind class strings and JSX attribute lists are the accepted exception — split them with `+` or one attribute per line rather than shrinking names |
| Blank lines | one between top-level declarations; none at the start or end of a block |
| Arrow functions | parentheses around a single parameter: `(rows) => rows` |
| Objects | shorthand properties; one property per line once the object wraps |

```ts
const sessions = drizzle(env.DB)
  .select()
  .from(sessionTable)
  .where(and(eq(sessionTable.userId, session.user.id), gt(sessionTable.expiresAt, new Date())))
  .then((rows) => rows);
```

## 2. TypeScript

- `strict` is on and stays on. Never add `// @ts-ignore` or `as any`; narrow
  `unknown` instead (see `authErrorMessage` in `app/lib/auth-actions.server.ts`).
- `import type { … }` for anything that is only a type. Inline `type` in a
  mixed import is fine: `import { serializeTheme, type Theme } from "../lib/theme"`.
- `interface` for object contracts and component props (`ButtonProps`,
  `RateLimitRule`); `type` for unions, aliases and derived shapes
  (`type ButtonVariant = keyof typeof variants`).
- Lookup tables are `as const` objects and their key union is derived with
  `keyof typeof`, never re-typed by hand.
- `satisfies` for config objects that must keep their literal shape
  (`] satisfies RouteConfig`).
- The non-null assertion `!` is reserved for `context.get(…)!` where middleware
  or `server.ts` guarantees the value. Anywhere else, handle the `undefined`.
- Route arguments are typed from the generated `Route` namespace
  (`Route.LoaderArgs`, `Route.ActionArgs`, `Route.ComponentProps`,
  `Route.MetaFunction`, `Route.MiddlewareFunction`). Never hand-write these.
- Action error objects are annotated `FormErrors` (or `Record<string, string>`)
  at the declaration site. Without it each branch infers its own literal
  shape and `actionData.errors.email` stops compiling.

## 3. Files and naming

| Thing | Convention | Example |
|---|---|---|
| Files | kebab-case | `auth-shell.tsx`, `rate-limit.server.ts` |
| Server-only module | `.server.ts` suffix — React Router fails the build if a client module imports it | `email.server.ts` |
| Client-only module | `.client.ts` suffix | `auth.client.ts` |
| Route module | flat under `app/routes/`, name = URL segment | `forgot-password.tsx` |
| Resource route | `api.<name>.tsx` | `api.theme.tsx` |
| UI primitive | `app/components/ui/<name>.tsx`, one primitive per file | `button.tsx` |
| Test | `tests/<feature>.spec.ts` | `ui-flow.spec.ts` |
| Components, types, interfaces | PascalCase | `EmptyState`, `ToastVariant` |
| Functions, variables, props | camelCase | `redirectWithSession`, `loggingOut` |
| Module-level constants | UPPER_SNAKE_CASE | `MIN_PASSWORD_LENGTH`, `DISMISS_AFTER_MS` |
| Booleans | read as a predicate | `submitting`, `hasGoogle`, `allowed` |
| Env / bindings | as generated by `cf-typegen`; never alias them | `env.DB`, `env.RESEND_API_KEY` |

Rename a column, a route or a table only together with the migration, the route
table and the tests that name it.

## 4. Modules and imports

- Relative paths only (`../lib/validation`). The `~/*` alias exists in
  `tsconfig.json` but nothing uses it; do not start.
- Import order, one group per line block, no blank lines between groups:
  1. `react`
  2. `react-router`
  3. third-party (`drizzle-orm`, `lucide-react`, `better-auth`, …)
  4. `../lib/*`
  5. `../db/*`
  6. `../components/*` — `ui/*` primitives after app-level components
  7. `import type { Route } from "./+types/<route>"` — always last
- Named exports everywhere. The only default export is a route module's
  component, and React Router requires that one.
- No barrel (`index.ts`) files. Import from the file that defines the symbol.
- No side effects at module scope: no bindings, no `new Date()` for config, no
  network. Anything per-request is created inside the loader/action.
- A module exports one concern. When a helper is only used by one route, it
  stays in that route file below the exports that use it.

## 5. Route modules

Order inside the file, top to bottom:

```
imports
export const meta
export const middleware      (layouts only)
export async function loader
type / const helpers the action needs (ActionResult, ok(), fail())
export async function action
local components (StatCard, StatSkeleton, …)
export default function Page
```

- Loaders `await` only what the shell needs. Slow queries are returned as
  promises and rendered with `<Suspense>` + `use()`. Start independent queries
  before awaiting any of them.
- Actions read fields through `field(form, name)` (trimmed string), validate,
  rate-limit, then call the service. They return
  `data({ errors, values }, { status: 400 })` on user error and
  `data({ errors }, { status: 429 })` when rate-limited; passwords are never
  echoed back in `values`.
- Pages with several forms use one action switched on a hidden `intent` field,
  with an `ActionResult` type and `ok()` / `fail()` helpers so every branch
  returns the same shape (`app/routes/settings.tsx`).
- Redirect **from a loader** with `throw redirect(…)`; **from an action** with
  `return redirect(…)` / `return redirectWithSession(…)`.
- A route registered for GET and POST answers both. Resource routes with only an
  `action` still export a `loader` that returns 405 with an `Allow` header.

## 6. Components

- Function components only. Props are an `interface <Name>Props`, extending the
  matching DOM attributes when the component wraps an element
  (`extends React.ButtonHTMLAttributes<HTMLButtonElement>`).
- React 19: `ref` is an ordinary prop. No `forwardRef`, no `React.FC`.
- Primitives set `data-slot="<name>"` on their root element and expose their
  style map (`buttonStyles`, `buttonVariants`) so links can look like buttons
  without nesting a `<button>` inside an `<a>`.
- `cn()` builds the class list: base, then variant, then size, then the
  caller's `className` last. `className` is for layout only; there is no
  tailwind-merge, so it cannot override base styles.
- Hooks are called unconditionally at the top of the component. Derived
  booleans come right after (`const submitting = navigation.formAction === "/login"`).
- Anything that must survive hydration (timestamps, theme) goes through the
  existing helper (`<LocalTime>`, `getTheme`) instead of reading `window`
  during render.

## 7. Comments

The single most visible house rule: **comments explain why, not what.**

- Every exported function, type and constant has a JSDoc block. It states the
  reason the symbol exists or the trap it avoids, not a restatement of its
  signature.
- When a rule exists because something broke, the comment says so:
  *"That gap is how a broken logout endpoint … shipped green."*
- Code that looks wrong on purpose gets an inline note at the line:
  `// NOT awaited on purpose`, `// Never trust this value: it lands in a Location header`.
- No commented-out code, no `TODO` without an owner and a reason, no
  changelog-style comments (git owns history).
- Comments are full sentences with a capital and a period. Wrap at the same
  width as code.

## 8. Errors and logging

- Log with a bracketed module tag, a short clause, then the error object:
  `console.error("[rate-limit] check failed, allowing request:", error)`.
  Tags in use: `[auth]`, `[rate-limit]`, `[email]`.
- Never render a dependency's raw message. Only 4xx text reaches the user
  (`responseErrorMessage`, `authErrorMessage`); 5xx bodies go to the log and
  the user gets the fallback sentence.
- Decide fail-open vs fail-closed explicitly and write it down: rate limiting
  fails **open** (a broken counter must not lock everyone out); auth and
  redirects fail **closed**.
- Side channels never throw into a request: `sendEmail` swallows and logs.
- User-facing strings are complete sentences ending in a period, written in the
  second person where natural ("Keep it under 80 characters.").

## 9. Tests

- One spec per feature in `tests/`, run in the real Workers runtime
  (`@cloudflare/vitest-pool-workers`). `beforeAll(() => setupDb(env))` applies
  every committed migration; nothing to register.
- Drive the route the browser hits (`SELF.fetch(formPost("/login", …))`), not
  the underlying API. Tests that only call `auth.api.*` miss broken forms.
- `describe("<feature>")` + `it("<does X> when <Y>")` in plain sentences:
  `it("rejects a short password with a field error instead of a redirect")`.
- Assert the contract, not the markup: status, `Location`, `Set-Cookie`,
  and a stable phrase from the body. Avoid asserting on class names.
- Shared helpers (`formPost`, `cookieHeader`) live at the top of the spec that
  needs them; promote to `tests/setup-db.ts`-style modules only when a second
  spec needs the same helper.
- A regression test opens with a comment naming the bug it pins.
- Fixtures use `@example.com` addresses. Nothing in tests may send real email
  or hit a real network.

## 10. Styling

- Tailwind v4 with the design tokens in `app/app.css`: `bg-background`,
  `text-muted-foreground`, `border-border`, `text-primary`. Raw palette classes
  (`bg-gray-50`) are a bug because they ignore dark mode.
- Class strings read layout → box → typography → colour → state
  (`"inline-flex items-center gap-2 rounded-md text-sm font-medium bg-primary hover:bg-primary/90"`).
- Long class lists are split into named `const` strings joined with `+`, as in
  `app/components/ui/button.tsx`, not left on one 200-character line.
- No inline `style={}` and no CSS files besides `app/app.css`.

## 11. Git

- Conventional Commits, matching the existing history:
  `type(scope): imperative summary` in lowercase, ≤ 72 characters, no period.
  Types in use: `feat`, `fix`, `refactor`, `chore`, `ci`, `docs`, `test`.
  Scope is optional (`fix(ci): …`, `feat(perf): …`).
- One logical change per commit. A schema change commits together with its
  generated `drizzle/*.sql` and the test that covers it.
- Never commit `.dev.vars`, `.env*`, `.wrangler/`, or `PLAN.md`
  (all listed in `.gitignore`).
- Agents do not commit or push unless the user asks in that conversation.

## 12. Documentation

- `AGENTS.md` is the single source of truth for agent and contributor
  instructions. `CLAUDE.md` contains only `@AGENTS.md` and is never edited.
- When you introduce a pattern that the next feature should copy, add it to
  `AGENTS.md` in the same change. When you leave something out of the core on
  purpose, write a recipe in `docs/recipes/` and list it in its README.
- Documentation is English. Prose in comments and docs uses full sentences.

## Definition of done

1. `bun run check` (typecheck, build, test) is green.
2. New behaviour has a spec that drives the route, not just the API.
3. No new runtime dependency, no raw palette class, no `any`, no unexplained `!`.
4. Every exported symbol has a JSDoc that says *why*.
5. `AGENTS.md` and this file still describe the code as it now is.
